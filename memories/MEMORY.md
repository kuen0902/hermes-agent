# 🛠️ AI Agent 系統操作限制與診斷筆記 (v1.0)
## I. 系統限制與功能缺口
1. **地理位置/POI 服務 (Maps)：** 缺乏穩定且可調用的專業地理定位/API 工具。
2. **通用網路搜尋 (Search Web)：** 缺乏可用的標準化、高權重網路搜尋工具接口。
3. **爬蟲防護機制：** 對外部網站的自動化訪問（如瀏覽器）容易被網站偵測到 Bot，缺乏穩定的繞過和反爬機制。
4. **資源訪問權限：** 某些技能（如 `apple-notes`）在當前運行環境中不可用。

## II. 戰略優化建議：
1. **技能/工具級：** 優先強化和穩定化 **POI/Maps API** 和**通用網路搜尋 API** 的工具組。
2. **流程/韌性級：** 必須實作**「多級降級與替代方案引導機制」**。當 A 工具失敗時，不應只是報錯，而應自動分析出與 A 目標相似 B/C 類別的替代方案，主動引導用戶選擇。

## III. 已驗證的知識產物：
*   用戶需要高度結構化、可驗證的流程和步驟（Skill）。
*   需要將發現的複雜解決方案儲存為 Skill，以提升效率。

**[成功的技能修復案例 (Case Study)]**\n
*   **目標功能：** 讀取 Apple Notes 的內容。\n*   **原始嘗試結果：** 技能存檔存在，但執行時始終報 `Tool 'apple-notes' does not exist.` 錯誤。\n*   **診斷結果：** 確立了問題是 Agent 運行核心無法初始化/調用此技能。\n*   **修復路徑：** 成功通過 `skill_view` 獲取到底層的 AppleScript ($`osascript`$) 規格。\n*   **最終成功的關鍵：** 不依賴高層級的 `apple-notes` Tool Call，而是直接使用 `terminal` 工具執行底層的 `osascript` 指令，繞過運行環境層級的缺口，成功實現了功能。\n*   **教訓 (Lesson Learned)：** 當遇到外部 API 封閉或技能層級無法調用時，必須回溯到**作業系統原始指令集**尋找可行的最小原子操作集。**這是處理外部設備依賴的黃金標準流程。**
